# Decisions

| Date | Decision | Rationale |
| --- | --- | --- |
| 2026-09-15 | Keep local persistence as the source of truth. | The app must remain usable offline; CloudKit is a reconciliation layer. |
| 2026-09-15 | Use Apple frameworks only for v1. | The specification calls for no dependencies or custom backend. |
| 2026-09-15 | Store D1 work on branch `dev` and push there until the delivery slices are complete. | Keeps in-progress work off `main` while the delivery loop completes. |
| 2026-09-15 | Project creation establishes the recorded version baseline (marketing 0.0.0, build 1); each later file-changing delivery increments the build number. | Matches the version inventory recorded before the project existed. |
| 2026-09-15 | Unit tests use the Swift Testing framework in a hosted `Forgot the MilkTests` target. | Xcode 27 default; satisfies the deterministic test-harness requirement. |
| 2026-09-15 | Keep the seed catalog in Swift source and verify it with `scripts/check_seed_catalog.sh` (mechanical spec-vs-seed audit) on every delivery. | Deterministic, repeatable verification with no external tooling; catches transcription drift. |
| 2026-09-15 | The personal list is titled "My List" and empty categories are hidden in D1. | Keeps the D1 surface minimal per the acceptance criteria; both are revisited in D2. |
| 2026-09-15 | In the catalog picker, needed catalog items are shown marked "Added" and non-selectable; completed ones stay selectable so selecting reopens them. | Makes the duplicate/reopen rule visible without hiding catalog state. |
| 2026-09-15 | Custom (non-catalog) items follow the same add/reopen rule matched by (category, normalized name): needed → no-op, completed → restore. | Extends spec rule 5 with the spec's normalization rule. |
| 2026-09-15 | "Save to catalog" is offered only when adding a custom item, not when editing a one-off item. | Keeps the edit form minimal per spec 4.2. |
| 2026-09-15 | The unit-system setting is a persisted value (default Imperial) plus a domain seam in D2; the settings UI and initial-unit suggestion ship with D4. | The settings screen is D4 scope; the suggestion rule never converts quantities. |
| 2026-09-15 | DEBUG-only launch arguments `resetDatabaseOnLaunch` and `contentSizeCategory` are the deterministic UI-test seams. | UI tests need a clean store and a forced Dynamic Type size without touching real settings. |
| 2026-09-15 | D2 adds an XCUITest target `Forgot the MilkUITests`; `scripts/verify.sh` runs unit tests then UI tests. | Spec section 7 requires UI-level coverage in the canonical harness. |
| 2026-09-17 | List-scoped destructive confirmations (delete item, clear completed) use `.alert` instead of `.confirmationDialog`. | On the iOS simulators tested, SwiftUI renders a List-anchored `confirmationDialog` as a top-anchored popover whose button container is sized for one button, clipping the second button out of the accessibility tree; a system alert always renders all buttons and keeps cancel reachable. The item form's delete confirmation keeps `confirmationDialog` because it renders correctly from its sheet context. |
| 2026-09-19 | UI tests treat a focused empty SwiftUI `TextField` whose AX value equals its placeholder as cleared, instead of asserting the value is `""`. | A cleared, focused `TextField` reports its placeholder (e.g. "Template name") as the accessibility value rather than an empty string, so an `isEmpty` condition on the value never observes the cleared state; keyboard backspace taps verified effective via a timestamped AX-value trace. |
| 2026-09-19 | The D4 entitlements include both the container identifier and `com.apple.developer.icloud-services` = `CloudKit` (not `CloudDocuments`). | Apple's entitlements documentation states the iCloud capability with the CloudKit service adds this entitlement for CloudKit-framework use, and Xcode's own CloudKit capability template (`App-CloudKit.entitlements`) uses exactly `CloudKit`; `CloudDocuments` is the iCloud Documents service, which this app does not use. |
| 2026-09-20 | Pass `cloudKitDatabase: .none` explicitly at every `ModelConfiguration` site (app store and test stores) instead of relying on the SDK default. | The iOS 27 SDK changed the default from `.none` to `.automatic`; with the committed CloudKit entitlement (which the Xcode launch/test pipeline applies to simulator processes), `.automatic` attempted CloudKit store integration and fatally failed store validation on non-optional `@Model` attributes, crashing app launch and the unit-test host. Offline-first requires the local store to never depend on CloudKit until the D4 reconciler is wired and the models are CloudKit-compatible (optional or defaulted attributes), when the sites switch to `.private("iCloud.com.hoaglun.forgotthemilk")`. |
| 2026-09-20 | Keep the `CloudKitClient` seam `@MainActor` and place the sync fakes (`FakeCloudKitClient`, `FakeCloudKitServer`, `FakeConnectivityMonitor`) under `#if DEBUG` in the app target instead of a separate test-support target. | All app code compiles to a single main-actor domain under `SWIFT_DEFAULT_ACTOR_ISOLATION`, so a `@MainActor` seam matches the future `CKContainer`-backed adapter and reconciler with no isolation friction; the fakes are consumed only by this app's own unit/UI tests, so `#if DEBUG` keeps release binaries clean without an extra build target to maintain. |
| 2026-09-20 | Make the fake CloudKit server deterministic: stamp every write with a controllable `serverNow` clock, attribute writes to the writing device (driving `shared` flags and last-writer-wins), serve snapshots in fixed `(type, id)` order, and consume injected auth/network/permission/quota/partial-save failures one-shot. | The D4 spec requires contract tests with "a controllable server clock ... injectable auth, permission, quota, network, and partial-failure errors, and a two-device fake pair"; per-device attribution plus the server clock lets one pair exercise sharing, conflict resolution, and delete tombstones end-to-end, and one-shot consumption keeps later operations independent of earlier injected failures. |
| 2026-09-21 | `scripts/verify.sh` runs the UI-test phase under a 30-minute watchdog and, on failure or timeout, retries the phase once on an erased simulator. | Xcode 26 runs UI tests on parallel simulator clones and `xcodebuild test` applies no per-test timeout; two observed wedges (a hung `testSaveTemplateFromToolbar` and a test-manager launch loop that never started a suite) both left `xcodebuild` idle forever on a wedged simulator, so the canonical gate needs its own bounded retry instead of hanging indefinitely. |
| 2026-09-21 | `testRenameTemplate` re-queries the keyboard backspace key every loop pass and taps it only while `isHittable`. | A stored element reference, or a key still settling after `setFocus`, can fail the `AXScrollToVisibleAction` that `tap()` performs (observed `kAXErrorFailure` under parallel-clone load); a fresh, hittable-gated query makes the bounded clear loop resilient to that transient state. |
| 2026-09-21 | D4 unit-test suites create their SwiftData context with `TestStore.makePlainContext` (plain `ModelContext(container)`) instead of `container.mainContext`. | In the iOS 27.0 simulator test host, `mainContext.insert` crashes the host nondeterministically with a bare SwiftData `EXC_BREAKPOINT` (SwiftData base + 615620, no Swift fatal-error text; the `.ips` caught a worker thread mid lazy type-metadata instantiation, consistent with a `mainContext` main-thread-dispatch race). The identical insert pattern passes in some runs and suites and crashes in others — coin flip, not a fixed trigger; a plain context dispatches no main-thread work and is reliable. Production injects `ModelContext` into the reconciler/coordinator (the app passes `mainContext`), so the plain-context tests exercise the same code path. |
| 2026-09-21 | `SyncCoordinator` hops its `onShareChange` and connectivity-change callbacks onto the main actor (`Task { @MainActor in ... }`) instead of mutating `@MainActor` state synchronously from the caller thread. | The seam closures are invoked from background queues by the real `CKShare`/`NWPathMonitor` adapters; touching `@MainActor` observable state from them is a latent data race under the project's Swift 5 minimal concurrency checking. The hop defers state application to the next main-actor turn, so deterministic tests must poll for the resulting state rather than assert immediately after triggering. |
| 2026-09-21 | `SyncReconciler` reports an `.authentication` failure for both `.restricted` and `.unavailable` auth statuses (no account / temporarily unavailable), leaving only `.notDetermined`/`.couldNotDetermine` as silent no-ops. | Spec §4.4 requires a plain-language state plus disabled sharing with a recovery instruction when iCloud is unavailable; previously `.unavailable` returned an empty successful report, so the sync state settled to idle and Settings showed a misleading "Up to date" while the account row said "Unavailable". Indeterminate statuses stay silent because they are transient and a spurious error would flash "iCloud sign-in needed" before the status resolves. |
| 2026-09-21 | UI tests assert `LabeledContent` row values by matching the row's accessibility identifier and checking the row's combined accessibility label (`"Account, Signed in"`) rather than searching for the value text as a standalone `staticText`. | SwiftUI renders a `LabeledContent` in a `List` as one accessibility element whose label is `"Label, Value"` (confirmed by an AX dump: the value text never appears as its own `staticText`); identifier + label-containment assertions are stable across text sizes, and lazy `List` sections off-screen at accessibility text size are reached by bounded `swipeUp` before asserting. |
