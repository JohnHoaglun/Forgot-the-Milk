# Architecture

The Xcode project, app shell, SwiftData schema, seed catalog, first-launch seeding, item use cases, the item-entry domain (`ItemDraft`, `ItemFormValidation`, `ItemEntryUseCases`), the template domain (`TemplateNameValidation`, `TemplateUseCases`, `TemplateApplyReport`), list grouping logic, the export text builder (`ListExport`), the email export seam (`EmailExportService` with `MailComposing`/`ShareSheetPresenting` platform adapters, system wrappers, and DEBUG fakes), the catalog picker, the item form (add/edit), the template and export sheets, the list screen, the unit-test harness, and the UI-test target exist. The D4 sync layer now contains the pure sync domain (`SyncRecord`/`SyncRecordMapping` with stable UUID identity and per-entity payloads; `ConflictPolicy` whole-record last-writer-wins; `MutationQueue`/`SyncBaselines` ordered unsynced-mutation queue; `SyncState` idle/reconciling/recoverable-error reducer) and two platform seams: the `@MainActor` `CloudKitClient` protocol (fetch/save/delete, share lifecycle, auth status, typed `CloudKitClientError`) with a DEBUG-only `FakeCloudKitClient`/`FakeCloudKitServer` (controllable server clock stamping every write, per-device write attribution driving `shared` flags and last-writer-wins, deterministic snapshot order, one-shot injectable auth/network/permission/quota/partial-save failures, two-device `pair()` for contract tests) and the `ConnectivityMonitoring` protocol with `SystemConnectivityMonitor` (`NWPathMonitor`, main-actor hop) and a DEBUG-only `FakeConnectivityMonitor` (change-only notifications). The reconciler, the real `CKContainer`-backed client adapter, and the sharing use cases are not yet wired. Views read through `@Query` and mutate only through `ItemUseCases`, `ItemEntryUseCases`, and `TemplateUseCases`; `AppSeeding` owns persistence setup; `ListGrouping`, `CatalogSearch`, and `ListExport` are pure UI-shaping or export logic. The intended boundary is:

`SwiftUI views → domain/use cases → local persistence → sync reconciliation adapters`

Local SwiftData persistence will remain available while offline and is the UI source of truth. CloudKit/CKShare is introduced only as a D4 reconciliation and sharing adapter; the app never calls CloudKit directly from views. Catalog data, mail/share-sheet presentation, the CloudKit client, and connectivity all have deterministic fakes.
